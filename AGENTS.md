## Common Commands

- Run the sim: `python3 cyber_civ.py`
- LLM-driven sim: `python3 cyber_civ_llm.py`
- Recovery subsystem tests (all): `python3 -m recovery.cli test` (167 tests: engine, service, signal, state, dashboard, hardening, MT940, xpub, BIP32, Bech32, ingest API, keep-alive, idempotency)
- Recovery demo: `python3 -m recovery.cli demo`
- Recovery API server: `python3 -m recovery.cli serve` (localhost:8000, HTTP Basic Auth from `recovery/.auth`)
- Signal sensing: `python3 -m recovery.cli sense <signal>` (tx hash, wallet address, `bank:<routing>:<account>`, or `ref:<reference>`)
- Fallback test: `python3 test_recovery_fallback.py`
- Adapter check: `python3 adapter_check.py`

## Project Layout

- `cyber_civ.py` — core sim engine.
- `cyber_civ_llm.py` — LLM-driven sim (Ollama llama3.2:3b locally; Meta Model API muse-spark-1.3 via opencode).
- `arbiter.py` — arbiter / decision logic.
- `adapter_check.py` — fine-tune adapter checks.
- `recovery/` — Recovery subsystem: deployable service for private + bank use (engine, HTTP API, signal monitor, persistence, dashboard, auto-cycle). See `recovery/README.md`.
- `docs/` — project docs.
- `training/` — fine-tuning data and scripts.
- `showcase-2026-10-31/`, `showcase-2026-11-01/` — showcase run outputs.
- `systemd/` — systemd units for the recovery API, auto-cycle, and tunnel (`restore-units.sh` restores them after a VM replacement).
